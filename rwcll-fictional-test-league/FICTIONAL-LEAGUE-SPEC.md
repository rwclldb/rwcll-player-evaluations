# RWCLL Fictional Test League Specification

**Status:** Draft fixture specification based on source inspection of `feature/admin-evaluation-review` on 2026-11-09.  
**Safety:** Specification only. No database, hosted project, or GitHub files were modified. All people and identifiers are synthetic.

## Purpose

Provide a repeatable 40–50-player fictional league to exercise the full season lifecycle:
1. Preserve a completed prior season.
2. Prepare a new Spring 2027 season.
3. Import registrations and resolve identity/status/age edge cases.
4. Schedule and conduct evaluations.
5. Review results, generate reports, and reconcile exports.
6. Close out and prepare the following season.

## Baseline scope

- 45 fictional players in the roster fixture.
- 10 fictional coaches, with a mixture of prior-season history, no history, incomplete history, conflicting matches, source-name variants, and coaches assigned to multiple teams.
- 5 independent evaluators.
- 2 administrators.
- Seasons: `Spring 2026` (completed historical season) and `Spring 2027` (new season under test).
- Active divisions: AA, AAA, Majors, Juniors, Seniors.
- Evaluation group key: official Little League age, not final division.
- Active age range for this fixture: ages 7–16; no age-6 player in the active evaluation pool.
- Registration statuses deliberately include `COMPLETED`, `PENDING`, `UNPAID`, and `UNKNOWN`.
- Imported source division is only source data; it must not be treated as the final post-draft assignment.
- Evaluation numbers are season-specific; some are intentionally blank.
- Synthetic Sports Connect IDs are external matching clues, not permanent RWCLL player IDs.

## Important age-data caution

The fixture's age column is the intended Spring 2027 scenario value. The synthetic birthdates are deliberately artificial and must not be used as an authoritative age calculation. Before using DOBs to validate eligibility, validate the official Spring 2027 age chart and calculation rule in the app. Do not infer or hardcode a real child's data.

## Fixture roster

`fictional_player_roster.csv` contains 45 synthetic player identities and scenario tags. A duplicate external ID is intentionally assigned to PLY-007 and PLY-008. PLY-019 is tagged as an external-ID-change match candidate. Rows tagged for attendance/exemption are scenario labels only; they do not mean those records can be persisted in the current schema.

## People and role fixture

`fictional_people.csv` contains 2 admins, 10 coaches, and 5 independent evaluators. It describes intended test roles, not actual Supabase Auth users. Create local test accounts and grant roles through the approved local workflow; never use real email addresses or credentials in fixture files.

## Historical-season design

Spring 2026 should contain:
- Returning players with prior-season coach ratings.
- Players with no prior-season history.
- At least one coach with a complete set of five core ratings.
- At least one incomplete historical record.
- At least one conflicting candidate match that must remain unresolved until an administrator decides.
- At least one source-name variant and changed external ID.
- Historical source coverage notes where only partial source spreadsheets exist.

Historical ratings are read-only context and must never be counted in Spring 2027 current evaluation averages or completion totals. Do not automatically create or merge player records from historical source rows.

## Spring 2027 workflow design

1. Create the season and ensure only the permitted division setup carries forward.
2. Stage a representative Sports Connect CSV, inspect flags, resolve candidates, and commit only approved rows.
3. Validate active registration statuses and age eligibility.
4. Configure one age-based evaluation session for each used age; add primary and makeup events.
5. Assign coaches and independent evaluators by session.
6. Evaluate a controlled subset with complete ratings, optional pitching/catching ratings, drafts, unknown experience answers, a Not Evaluated case, and deliberate evaluator disagreement.
7. Review player reports and CSV exports. Compare displayed totals and exported rows against expected counts.
8. Test post-draft assignment and season closeout only where the app has supported workflows; mark unsupported scenarios blocked rather than simulating success by direct SQL.

## Safety and execution rules

- Do not insert these records into either database until the fixture is checked against the current schema and the user approves the next step.
- First use a disposable local database or a clearly isolated local fixture namespace.
- Do not reset or truncate the user's current local database without explaining the impact and receiving approval.
- Do not apply migrations, insert test data, or otherwise modify hosted Supabase.
- Use stable synthetic keys in CSVs; database identity values should be generated by the database and mapped to these keys in the test harness.
- Keep source registration IDs, permanent player identity, season registration, historical evaluation, current evaluation, attendance, and team assignment conceptually separate.
- Any test for attendance, exemptions, full historical import, roster assignment, or close/reopen audit must be marked blocked until its feature is verified.

## Source-inspection findings and limits

A database column or design decision alone is not proof of a complete user workflow.
